# 下一站 巨星

一个以训练、比赛和球员成长为主的篮球生涯游戏。你从江岚中学起步，练出自己的打法，争取青年队、CBA、海外联赛和 NBA 的机会。

当前版本：**V0.21**（文字战报与关键片段）。手机以**竖屏**游玩，电脑支持键盘。

[开始游戏](https://lynch715.github.io/next-stop-superstar/) · [GitHub 仓库](https://github.com/Lynch715/next-stop-superstar)

## 桌面与主屏幕

网页图标和应用名称为 **下一站巨星**，包含浏览器图标、Apple 主屏幕图标和 192／512 像素应用图标。

- Mac：用 Safari 打开游戏，选择“文件 → 添加到程序坞”，名称填“下一站巨星”。[Apple 说明](https://support.apple.com/zh-cn/104996)
- Chrome：菜单“投放、保存和分享 → 将网页安装为应用…”。[Chrome 说明](https://support.google.com/chrome/answer/9658361?hl=zh-CN)
- iPhone：用 Safari 打开游戏，在分享菜单中选择“添加到主屏幕”。

首次载入需要联网。进度仍保存在浏览器中；安装或切换浏览器前先导出存档。

## 游戏内容

- 三类起点：灵巧后卫、得分侧翼、潜力内线。专项训练、恢复、位置竞争和招牌能力贯穿生涯。
- 文字比赛为主：战报推进全场，通常穿插三次约 20 秒的关键片段，亲手完成快攻、投篮、传球、挡拆、争板或防守。片段结束后回到战报，不需要打满整场。
- 完整职业赛季：NBA 30 队、每队 82 场；CBA 20 队、每队 38 场；另有目前收录的 10 支 NBA G League 球队。包含排名、季后赛、试训、选秀和合同。
- 职业球队使用真实队名和队徽。球员名单、能力、合同、比赛结果由游戏生成，赛程安排作了游戏化简化。
- 训练与角色逐步成长。高阶能力需要多次积累，密集赛程仍需安排恢复。

## 怎么打

大部分时间通过文字战报推进比赛，关键时刻可以亲手上场，也可以交给教练。自由练习仍可完整体验连续攻防。

小游戏中，手机左手拖动摇杆跑位，轻推慢走，松手停止。右手按住投篮，力度进入绿区后松手；也可以轻点蓄力，再点一次出手。点队友名字传球，用掩护和要球完成配合；抢篮板先卡位，防守时跟住持球人，再找时机抢断或封盖。

电脑使用 WASD 或方向键移动，空格按住后松手投篮；1／2／3 传球，R 要球，E 掩护；F 跟防，B 卡位或稳守，防守时空格抢断或封盖。

随时可以暂停、保存离场，回来继续这场比赛。自由练习不消耗体力。

## 本地运行

无需安装前端依赖。在项目目录启动静态服务后，用浏览器访问 HTTP 地址：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8765/`。手机访问电脑上的开发服务需要另行配置局域网访问；公开游玩可部署到 GitHub Pages。

## 存档

进度保存在当前浏览器。换手机、换网址或清理浏览器前，先在设置中导出，再到新地址导入。存档不会自动跨域名或端口迁移。

旧版球员、属性、训练资源、合同和比赛记录继续保留。旧 NBA/CBA 赛季沿原赛程打完，下季进入扩容联赛。旧实操中途存档也可以续打，或模拟剩余时间；下一场采用文字战报与关键片段。更新不会清空当前网址下的旧存档。

## 构建与发布

```sh
node test-mobile.cjs
node test-highlights.cjs
python3 tools/build_release.py
python3 tools/check_release.py
```

生成：

- `dist/`：可直接托管的网站。
- `release/下一站巨星-v0.21-网站.zip`：纯静态网站包。
- `release/下一站巨星-v0.21-源码.zip`：包含构建脚本、移动输入回归和 GitHub Pages 工作流。

发布流程见 [发布说明](发布说明.md)。工作流由手动触发，构建检查后仅部署 `dist`。网站包与源码包均不包含测试球员存档、验收截图或本机私有文件。

移动输入回归可独立运行，涵盖摇杆、多指操作、投篮手势、中断恢复、保存节流和竖屏坐标。完整赛季与历史版本回归在本地保留，依赖未放入公开包的测试数据。

公开版本通过 GitHub Actions 构建并发布到 Pages。浏览器竖屏验收不等同于真实手机硬件验收。图标源文件为 `icon.svg`，可选用 Pillow 运行 `python3 tools/make_app_icons.py` 重新生成 PNG；正常构建不需要 Pillow。
